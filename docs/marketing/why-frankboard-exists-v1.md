# FrankBoard — Why We Exist (Page Outline v1)

**Date**: 2025-03-15  
**Status**: Strategy document  
**Scope**: "Why FrankBoard exists" page structure — story, positioning, rationale.

---

## Story Angle

FrankBoard exists because small teams deserve a work board that is **simple to run and straightforward to use** — without the complexity of enterprise tools or the rough edges of abandonware. We're building the evolution we wished existed when we ran Kanboard ourselves.

---

## Positioning Angle

- **Evolution, not revolution**: FrankBoard is a modernization fork, not a from-scratch rewrite. We respect what Kanboard got right: simplicity, self-hosting, low overhead.
- **For small teams, by small teams**: Built by people who run small teams. We avoid features we wouldn't use ourselves.
- **Commercially sustainable**: Open community edition; optional Pro and Cloud for teams that want support or managed hosting. We're here for the long haul.

---

## Why the Product Was Created

1. **UX gap**: Kanboard's core is solid, but the UI felt dated. We wanted cleaner typography, consistent spacing, better board and task layouts — without changing how the product works.

2. **Deployment clarity**: Docker + PostgreSQL as the default path. VPS-first, documented. No guessing about how to run it.

3. **Commercial path**: Kanboard has no commercial offering. Teams wanting support or managed hosting had nowhere to go. FrankBoard provides a clear path: Community (free) → Pro (support, license) → Cloud (managed).

4. **Continuity**: Kanboard users shouldn't have to abandon their setup. FrankBoard preserves compatibility so migration is practical and reversible.

---

## What Problem It Solves

| Problem | FrankBoard response |
|---------|----------------------|
| "Kanboard works but looks rough" | Modernized UI; same workflows |
| "I need support for my team" | Pro: commercial license + priority support |
| "I don't want to host it myself" | Cloud: managed, we run it |
| "Enterprise tools are overkill" | Simple boards; no SSO, audit trails, or bloat |
| "I want to keep my data on-prem" | Self-hosted Community and Pro |

---

## What It Deliberately Refuses to Become

- **Not a Jira clone**: No custom fields, complex workflows, or enterprise SSO. We stay simple.
- **Not AI-first**: No AI-generated tasks, automation hype, or "AI-powered" claims. We focus on clarity and usability.
- **Not a SaaS-only product**: Self-hosted remains first-class. Cloud is an option for those who prefer it.
- **Not a hostile fork**: We don't bash Kanboard. We're a respectful evolution.
